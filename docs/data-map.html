01 · The tables

documents — the frozen source

One row per thing received (file, photo, or forwarded link). Saved exactly as it arrived and never edited afterwards — this is the evidence everything else points back to.

documentssource records · one row per received file/photo/linkLIVE
ColumnAllowed valuesWhat it is
idauto-number (1, 2, 3…)Unique forever; what links point at
owner_ida users.idWhose document this is — every table has this
categorytravelid_legalreceiptsotheremptyFiling label for the Files page. Empty = predates the feature or couldn't be classified
titleshort text, or emptyAI-written name, e.g. "Ryanair Boarding Pass, Faro"
extracted_textfree textEverything readable in the document; what search looks through
filename · mime_type · stored_path · caption · phonetextThe original file's name/format, where the encrypted copy lives on disk, what you typed when sending, which phone sent it

entities — the typed facts

One row per structured fact derived from a document (or logged by your phone). The type column says what kind of fact; the data column holds that type's specific fields as JSON — which is why new types need no new tables.

entitiesderived facts · one row per check-in / expense / booking / tripLIVE

statusactiveneeds_reviewarchivedLifecycle. A shaky-but-plausible extraction is stored as needs_review instead of being silently trusted or dropped
dataJSON — shape depends on type, see belowThe fact's actual fields

example row → id: 47 · owner_id: 1 · type: travel_checkin · status: active · data: { country: "Portugal", city: "Faro", checkedInAt: 12 Jun 2026, source: "document" } · confidence: 0.9

links — the connections

One row per connection between two records. Each side can be an entity or a document, named by its id. This replaces hardwired one-to-one references with connections you can add freely — many things can point at the same trip.

03 · Why links exist

The picture this is all building toward

A trip entity becomes the anchor everything attaches to. "Everything for the Faro trip" is then one walk along belongs_to links — no searching. Note the boarding pass feeding two entities: something a folder system can't express.
